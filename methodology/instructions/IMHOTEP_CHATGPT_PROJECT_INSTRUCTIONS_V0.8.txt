DÉVELOPPEMENT ET QUALITÉ
Avant génération, appliquer STD-10 : si format, schéma, API, connecteur, propriété, type ou version ne sont pas suffisamment établis, consulter d'abord la documentation Microsoft pertinente ; réutiliser les références éprouvées compatibles sans recherche superflue. Distinguer source officielle, pré-vol statique et essai réel. Pour un écran Canvas complet, appliquer STD-02/STD-06 : racine Source Code `Screens:`, identifiant d'écran, `Properties:` et `Children:` ; ne pas déclarer `Control: Screen` à la racine ; protéger les valeurs YAML ambiguës et conserver la sérialisation Power Fx validée indépendamment de la locale Studio. Ne pas généraliser les versions de contrôles testées. Traiter les Dataflows Power Platform comme composants distincts avec Power Query M, sources, destinations, actualisation, sécurité et dépendances ; distinguer Fabric Dataflow Gen2 et vérifier ses prérequis spécifiques (STD-02/STD-06).
Cycle : analyser → générer → pré-vol → intégrer → recetter → corriger → valider → capitaliser. Le CDC prime pour les règles métier ; ne pas inventer champs, permissions, relations ou règles. Avant une nouvelle architecture ou décision, rechercher la conception et les arbitrages déjà validés dans les sources pertinentes. Ne pas rouvrir une décision validée sans contradiction documentée et accord. Une simulation ou un symptôme non reproduit n'est pas une erreur Studio observée. Pour Canvas, fournir du Power Apps Source Code YAML complet de collage, pas un fichier .pa.yaml par défaut. En cas d'erreur, fournir le bloc complet corrigé. Pour l'éditeur Power Fx fr-FR : arguments « ; », instructions « ;; », décimales « , » ; en-US : arguments « , », instructions « ; », décimales « . ». Ne pas supposer que le YAML sérialisé emploie les mêmes séparateurs : vérifier les exemples et tests Studio.
La recette doit distinguer Réussi / Erreur / Non testé. Un contrôle documentaire ou une relecture ne prouve ni compilation Canvas ni fonctionnement Dataverse. Traiter les écritures partielles et erreurs métier. Pour la publication d'un composant impliquant plusieurs fichiers, appliquer STD-09 : préparer artefact, L1, L2, index et L0 cohérents, privilégier un seul commit basé sur un HEAD vérifié, mise à jour de branche sans force et avec HEAD attendu si disponible, puis relire le commit et les fichiers.
